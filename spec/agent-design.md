# תכנון הסוכן: אתר + טלגרם

> מסמך תכנון לחיבור FitnessBot לאתר, בלי לאבד את ערוץ הטלגרם. נכתב ב-2026-09-26, לפני הבנייה.
> סטטוס: **טיוטה לאישור.** ההחלטות הפתוחות מסומנות ב-⚠️ בסעיף 9.

## 1. העיקרון

**סוכן אחד, שני ערוצים, כרטיס לקוח אחד.**

- **האתר מוכר.** המבקר אנונימי ועוד לא לקוח. הסוכן עונה ממאגר הידע, מוריד חששות ומוביל להשארת פרטים.
- **טלגרם מלווה.** המתאמן מזוהה. שם הוא מעדכן שקילות, ושם מגיעה התזכורת השבועית.
- **כרטיס הלקוח מחבר ביניהם.** כשמבקר משאיר פרטים באתר נוצר כרטיס, וכשהוא מתחבר לבוט בטלגרם הבוט מכיר אותו.

השיחות עצמן לא עוברות בין הערוצים. מה שעובר הוא הכרטיס: פרטים, מטרה, מסלול מומלץ ותקציר קצר של מה שהעסיק אותו.

## 3. וורקפלואו A: הסוכן

### 3.1 נרמול

שני הטריגרים מתורגמים לאותו מבנה, כך שהסוכן לא צריך לדעת מאיפה ההודעה הגיעה:

| שדה | טלגרם | אתר |
|---|---|---|
| `channel` | `telegram` | `web` |
| `user_key` | `tg:<chat.id>` | `web:<session_id>` |
| `telegram_id` | `chat.id` | ריק |
| `text` | `message.text` | `body.message` |

- **זיכרון השיחה** לפי `user_key`. הקידומת מבטיחה ששיחה מהאתר ושיחה מטלגרם לא יתערבבו.
- **ההקשר שמוזרק לסוכן** בראש כל הודעה: `[channel: web]` או `[channel: telegram]`, במקום `[telegram_id: X]` של היום.

### 3.2 הרשאות לפי ערוץ

| כלי | אתר | טלגרם | הערה |
|---|---|---|---|
| Pinecone Knowledge Base | ✅ | ✅ | |
| Get Member | ❌ | ✅ | |
| Save Member | ❌ | ✅ | מחפש קודם לפי טלפון (סעיף 5) |
| Supabase Database (שקילה) | ❌ | ✅ | |

**למה:** באתר אין אימות. אם הכלים יפעלו שם, מבקר יכול לכתוב "אני 050-1234567, שקלתי 80" ולעדכן משקל של מישהו אחר.

**איך נאכף:** במבנה ולא בפרומפט. אחרי הנרמול, צומת Switch מפצל לפי ערוץ לשני צומתי סוכן:
- **נציג – אתר:** מחובר רק לכלי מאגר הידע. לכלי השקילה והמתאמנים אין לו גישה בכלל, כך ששום ניסוח של המבקר לא יפעיל אותם.
- **נציג – טלגרם:** כל הכלים, כמו היום. ה-`telegram_id` בכלים נלקח מהטריגר בביטוי (`{{ ... }}`) ולא מ-`$fromAI`, כדי שהמודל לא יוכל להחליף אותו.

שני הסוכנים משתמשים באותו מודל ובאותו זיכרון. הפרומפט בנוי מבסיס משותף שיושב בצומת Set אחד, ומתוספת קצרה לכל ערוץ, כך שתיקון בבסיס חל על שניהם. בפרומפט של האתר: לבקשת שקילה, להפנות לבוט בטלגרם.

**תיעוד:** שני הערוצים נרשמים ל-`chat_logs` עם `channel` ו-`user_key` (סעיף 6).

### 3.3 הפרומפט

- הגדרת תפקיד לכל ערוץ (סעיף 1).
- באתר: לא לבקש שם וטלפון בתחילת שיחה. ההצעה להשאיר פרטים מגיעה אחרי שנתן ערך, והיא מפנה לטופס באתר.
- באתר, כששואלים על תרגיל: להפנות לעמוד הטכניקה. האתר כבר יודע להציג קישור `technique.html#<id>` אם התשובה מחזירה `link`.
- ניקוי השאריות `[cite: 1]` ושגיאת הכתיב "חיsearch".

### 3.4 תיקונים נלווים

- **Error Handler:** הסוכן והתזכורת מפנים היום ל-Error Handler המקורי (`73hkLvUCHaWHnKzG`). להחליף לשכפול של הפרויקט (`mYRljPDGJ6yqTZXF`).
- **תזכורת שבועית:** "השבוע" מחושב היום מיום שני, ולכן מי שנשקל ביום שני הקודם לא יקבל תזכורת. להחליף ל"7 הימים האחרונים".

## 4. וורקפלואו B: טופס הליד (האוטומציה)

1. **`POST /lead`** מקבל את הטופס ומחזיר מיד `{ job_id }`. בשלב הזה נוצרת שורה ב-`lead_jobs` עם `status: pending`.
2. **התאמת מסלול:** מודל שפה עם גישה למאגר הידע מחזיר מסלול (Foundation / Builder / Plateau Breaker) ונימוק של 1–2 משפטים, לפי המטרה ולפי תקציר שיחת האתר, אם הייתה.
3. **כרטיס לקוח:** upsert לטבלת `members` לפי טלפון (סעיף 5).
4. **הכלי החדש** (⚠️ החלטה 2): מייל לצוות עם פרטי הליד, המסלול והתקציר, ומייל אישור ללקוח עם המסלול וקישור לבוט בטלגרם.
5. **סיום:** `lead_jobs.status = done` עם המסלול והנימוק.

**`GET /lead-status?job_id=...`** מחזיר את מצב המשימה. האתר שואל כל 1.5 שניות, עד 20 פעמים (30 שניות).

**תקציר שיחת האתר:** הטופס שולח `session_id`. וורקפלואו B מושך את ההודעות של `web:<session_id>` מ-`chat_logs` ומסכם אותן במשפט או שניים. אם אין שיחה, התקציר ריק.

## 5. כרטיס הלקוח וחיבור לטלגרם

**המפתח המשותף הוא מספר הטלפון.**

1. באתר: הטופס יוצר כרטיס עם טלפון, ו-`telegram_id` ריק.
2. במסך התוצאה באתר ובמייל האישור: כפתור "התחברו לבוט בטלגרם לליווי ותזכורות".
3. בטלגרם, Get Member לא מוצא את ה-`telegram_id`, והבוט מבקש שם וטלפון. Save Member מחפש כרטיס לפי הטלפון:
   - **נמצא** (הגיע מהאתר): משלים בו את ה-`telegram_id`, ופותח את השיחה עם מה שיש בכרטיס ("ראיתי שאתה מתעניין ב-Plateau Breaker...").
   - **לא נמצא:** יוצר כרטיס חדש, כמו היום.
4. מאותו רגע התזכורת השבועית מגיעה אליו, כי היא עובדת לפי `telegram_id`.

**שדרוג אפשרי, לא בשלב הזה:** קישור `t.me/<bot>?start=<קוד>` שמזהה את הלקוח בלי להקליד טלפון.

## 6. Supabase

⚠️ המבנה הקיים של הטבלאות לא נבדק מכאן. לפני ההרצה צריך להשוות מול הטבלאות בפועל.

```sql
-- כרטיס הלקוח: הרחבה של members
alter table members alter column telegram_id drop not null;
alter table members add column if not exists email text;
alter table members add column if not exists goal text;               -- mass / cut / plateau / unsure
alter table members add column if not exists recommended_track text;
alter table members add column if not exists summary text;            -- תקציר שיחת האתר
alter table members add column if not exists source text default 'telegram';  -- web / telegram
alter table members add column if not exists marketing_consent boolean default false;
alter table members add column if not exists created_at timestamptz default now();
create unique index if not exists members_phone_key on members (phone);

-- משימות הטופס, בשביל ה-polling
create table if not exists lead_jobs (
  job_id uuid primary key default gen_random_uuid(),
  status text not null default 'pending',  -- pending / done / error
  track text,
  why text,
  created_at timestamptz default now()
);

-- תיעוד שיחות משני הערוצים
alter table chat_logs add column if not exists channel text default 'telegram';
alter table chat_logs add column if not exists user_key text;
```

## 7. חוזים מול האתר

כל ה-webhooks: `Access-Control-Allow-Origin` לכתובת האתר בלבד (ולא `*`), ובקשות `OPTIONS` נענות.

| נקודה | בקשה | תשובה |
|---|---|---|
| `POST /chat` | `{ session_id, message }` | `{ reply, link? }` — `link` הוא `{ href: "technique.html#<id>", label }` |
| `POST /lead` | `{ name, phone, email, goal, privacy, marketing, session_id }` | `{ job_id }` |
| `GET /lead-status?job_id=` | — | `{ done: false }` או `{ done: true, track, why }` |

**שגיאות:** האתר כבר מציג הודעה מעשית (ניסיון חוזר או וואטסאפ) על כל תשובה שאינה 2xx, ועל טופס שלא הסתיים תוך 30 שניות. בצד n8n: תשובת שגיאה עם קוד 500, ובמשימת טופס שנכשלה `status: error`, כדי שהאתר יפסיק לחכות מיד.

**שינויים באתר:**
- מילוי שלוש הכתובות ב-`ENDPOINTS` שב-`app/main.js`.
- הפסקת ה-polling כשמתקבל `status: error`.
- כפתור טלגרם במסך התוצאה.
